# 범위와 조건

이 문서는 결과를 읽을 때 같이 읽어야 하는 조건입니다. 수치는 아래 범위 안에서 뜻이 있습니다.

## 데이터와 과제

- **공개 벤치마크 4개**(ETTh1, ETTh2, Jena weather, UCI electricity 20채널)를 시간순으로 재생합니다. 재학습이 필요한 정도는
  데이터마다 크게 다르므로, 결론은 이 네 데이터셋과 같은 성격(시간 단위, 수 채널~수십 채널, 계절성)의 데이터에 적용됩니다.
  다른 도메인에서는 같은 캐시 절차로 다시 측정하면 됩니다.
- `electricity20` 은 321개 고객 중 **사전에 고정한 20개** 채널입니다(CPU 예산에 맞춘 선택).
- 과제는 L=336 → H=96 다변량 예측입니다. 짧은 지평이나 단변량 과제는 같은 설정 파일로 따로 실험합니다.
- 평가 척도는 초기 학습 구간의 표준편차로 고정한 MAE 입니다. 금액·운영 KPI 환산은 데이터 소유자의 비용 모델을 붙이는 단계입니다.

## 모델과 학습

- 재학습 정책 비교는 **DLinear** 로 고정했습니다. 캐시가 정책 수와 무관하게 "스트림 일수 × 시드" 번 학습하므로, 가벼운 모델이
  네 데이터셋을 CPU 예산 안에서 감당합니다. 네 계열(Linear·NLinear·DLinear·PatchTST)은 같은 분할의 리더보드와 데모의
  후보 학습·승격 게이트에서 비교합니다.
- 학습 예산은 최대 10 epoch, lr 반감, patience 3 입니다. 캐시의 많은 재학습이 10 epoch 상한에 닿았습니다
  (`artifacts/cache/*.json` 의 `fit.epochs`). 예산은 설정값이라 늘려서 같은 절차로 다시 돌릴 수 있습니다.
- 콜드 재학습은 매일 00:00 데이터까지로 학습하고 **다음 날부터** 서빙한다고 가정합니다. 즉시 배포가 가능한
  환경에서는 모든 정책의 이득이 조금 커집니다.

## 정책과 통계

- 감시 기반 정책의 하이퍼파라미터 격자(P7)는 사전에 고정했고 **격자 전체를 보고**합니다. 한 데이터셋에서 가장 좋은 점만
  골라 말하지 않고 격자 전체를 같이 보입니다.
- `+gate` 변형은 첫 결과를 본 뒤 추가한 **사후 탐색**이며, 프로토콜 가설(H1~H4) 판정과 분리해 보고합니다.
- 신뢰구간은 7일 블록 페어드 부트스트랩이며 시드별 구간의 평균을 보고합니다. 사전 등록 시드는 3개이고, etth1·etth2·weather 는
  사후에 8개로 늘려 분산을 확인했습니다(헤드라인은 3개 그대로, 확장은 results.md). electricity20 은 시드당 2시간 이상이라 3개입니다.
- 재학습 비용은 이 머신(4 vCPU, 1 스레드/프로세스)에서 측정한 학습 초입니다. 다른 하드웨어에서는 절대값이 다릅니다.

## 논문 재현

- 논문 보고값은 `artifacts/paper_reference.json` 에 **사람이 옮겨 적은 값**이며 원문 표와 함께 읽습니다.
- PatchTST 는 논문 설명대로 구현했고, 참조 코드와의 차이(residual attention)는 `models/patchtst.py` 에 적어 두었습니다.
- PatchTST 재현은 H=96, 시드 1개입니다(CPU 예산). 나머지 지평은 같은 러너로 실행합니다.

## 서비스

- 공개 데모 이미지(`Dockerfile.demo`)는 API 와 worker 를 한 프로세스에 둡니다. 운영 구성은 `Dockerfile` + `Dockerfile.worker`
  이며, compose 와 Kubernetes 매니페스트가 그 구성을 씁니다. 인증은 API 키 하나입니다.
- 레지스트리는 디스크 디렉터리 하나이고 버전은 해시와 참조 입출력으로 검증합니다. api 와 worker 는 같은 디렉터리를 공유합니다
  (compose 볼륨, Kubernetes 공유 PVC). 롤백은 이전 버전을 다시 검증해 활성화합니다.
- 지연 수치는 모델 호출(NumPy 입출력), loopback HTTP, 동시 클라이언트 1·8·32 의 처리량을 같은 머신에서 측정한 값입니다.
  네트워크 왕복은 `cloud-smoke` 의 실행 요약에 주소별로 기록됩니다.
- 리플레이는 기록된 데이터를 시간순으로 흘려 실시간 수집기의 자리를 대신합니다. 감시는 실제값이 도착해 해결된 오차만 봅니다.

## 대용량 처리

- 세 엔진 비교(Polars / pandas / PySpark `local[4]`)는 M4(100,000개 시계열, 24M 셀) 한 작업을 한 머신에서 돌린 것이고,
  electricity(321 채널)·traffic(862 채널)은 Polars 전처리 파이프라인으로 처리했습니다. 같은 Spark 작업을 standalone
  클러스터(master 1 + worker 2, 컨테이너 3개, vCPU 4개 호스트 하나, 로컬 볼륨)에서도 돌려 결과 일치와 worker 간 태스크 분배를
  확인합니다. 검사는 세 엔진의 셀 수·집계 일치이며, Spark 가 이 작업에서 두 자릿수 느린 이유는 [bigdata.md](bigdata.md) 에 적었습니다.
