# 한계와 주장하지 않는 것

이 문서는 결과를 읽을 때 같이 읽어야 하는 조건입니다. 좋게 나온 수치도 아래 범위 안에서만 뜻이 있습니다.

## 데이터와 과제

- **공개 벤치마크 4개**(ETTh1, ETTh2, Jena weather, UCI electricity 20채널)이며 실제 고객·설비 데이터가 아닙니다.
  재학습이 필요한 정도는 데이터마다 크게 다르고, 여기서 본 결론이 다른 도메인에 그대로 옮겨진다고 주장하지 않습니다.
- `electricity20` 은 321개 고객 중 **사전에 고정한 20개**입니다. 전체 321채널의 일 단위 캐시는 CPU 예산을 넘겼습니다.
- 과제는 L=336 → H=96 다변량 예측 한 가지입니다. 짧은 지평이나 단변량 과제에서 재학습의 가치는 다를 수 있습니다.
- 평가 척도는 초기 학습 구간의 표준편차로 고정한 MAE 입니다. 금액·운영 KPI 로 환산하지 않았습니다.

## 모델과 학습

- 재학습 정책 비교는 **DLinear 하나**로 고정했습니다. 더 큰 모델(PatchTST 등)에서는 재학습 비용과 이득의 비율이
  달라질 수 있으며, 이 프로젝트는 그것을 측정하지 않았습니다.
- 학습 예산은 최대 10 epoch, lr 반감, patience 3 입니다. 캐시의 많은 재학습이 10 epoch 상한에 닿았습니다
  (`artifacts/cache/*.json` 의 `fit.epochs`). 더 긴 예산이 결론을 바꾸는지는 확인하지 않았습니다.
- 콜드 재학습은 매일 00:00 데이터까지로 학습하고 **다음 날부터** 서빙한다고 가정합니다. 즉시 배포가 가능한
  환경에서는 모든 정책의 이득이 조금 커집니다.

## 정책과 통계

- 감시 기반 정책의 하이퍼파라미터 격자(P7)는 사전에 고정했고 **격자 전체를 보고**합니다. 한 데이터셋에서 가장 좋은 점을
  고른 뒤 그 점만 말하지 않습니다. 격자 밖의 값이 더 좋을 수 있습니다.
- `+gate` 변형은 첫 결과를 본 뒤 추가한 **사후 탐색**입니다. 프로토콜 가설(H1~H4) 판정에는 쓰지 않습니다.
- 신뢰구간은 7일 블록 페어드 부트스트랩이며 시드별 구간의 평균을 보고합니다. 시드 3개는 분산을 보기엔 적습니다.
- 재학습 비용은 이 머신(4 vCPU, 1 스레드/프로세스)에서 측정한 학습 초입니다. 다른 하드웨어에서는 절대값이 다릅니다.

## 논문 재현

- 논문 보고값은 `artifacts/paper_reference.json` 에 **사람이 옮겨 적은 값**입니다. 원문 표와 다시 대조해야 합니다.
- PatchTST 구현은 논문 설명을 따랐으나 참조 코드의 residual attention 은 넣지 않았습니다(`models/patchtst.py` 참고).
- CPU 예산 때문에 PatchTST 는 H=96 만, 시드 1개로 실행했습니다. 논문 전체 표의 재현이 아닙니다.

## 서비스

- 공개 데모 이미지(`Dockerfile.demo`)는 API 와 worker 를 한 프로세스에 둡니다. 운영 구성은 `Dockerfile` + `Dockerfile.worker`
  입니다. 인증은 API 키 하나이며 사용자·권한 체계가 없습니다.
- 레지스트리는 단일 디스크 디렉터리입니다. 다중 인스턴스 간 동기화, 서명, 자동 롤백은 없습니다.
- 지연 수치는 모델 호출(NumPy 입출력)과 loopback HTTP 를 각각 측정한 것이며 네트워크·부하·SLA 를 뜻하지 않습니다.
- 리플레이는 기록된 데이터를 시간순으로 흘리는 것입니다. 실시간 수집기·메시지 큐·지연 도착 처리는 범위 밖입니다.

## 대용량 처리

- M4(100,000개 시계열)·electricity·traffic 은 한 머신의 Polars / pandas / PySpark `local[4]` 로 처리했습니다.
  다중 노드 클러스터 운영을 주장하지 않습니다. 세 엔진의 셀 수·집계가 같다는 것만 검사합니다.

  것이며 다인 협업 이력을 주장하지 않습니다.
