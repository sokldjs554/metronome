# 실험 프로토콜 (사전 등록)

이 문서는 **실험을 실행하기 전에** 데이터, 분할, 모델, 정책, 지표, 판정 기준을 고정합니다.
결과를 본 뒤에 바꾼 항목은 아래 "변경 이력"에 날짜와 이유를 남깁니다. 결과 문서([results.md](results.md))는
이 프로토콜의 항목 번호를 인용합니다.

작성일: 2026-10-06 · 상태: 고정

## P1. 질문

배포된 시계열 예측 모델을 **언제 다시 학습해야 하는가.**

- 재학습을 하지 않으면(static) 1년 동안 얼마나 나빠지는가
- 매일 다시 학습하면(최대 신선도) 얼마나 좋아지며, 그 비용은 얼마인가
- 오차를 감시해 필요할 때만 재학습하는 정책이 주기 재학습과 같은 재학습 횟수에서 더 낮은 오차를 내는가

재학습 정책은 **모델을 바꾸지 않고** 비교합니다. 모델 구조 개선과 재학습 정책의 효과를 섞지 않기 위해서입니다.

## P2. 데이터

모든 데이터는 공개 벤치마크이며 다운로드 URL과 SHA-256을 `src/metronome/data/sources.py`에 고정합니다.

| 키 | 출처 | 채널 | 주기 | 길이 | 스트림(평가) 구간 |
|---|---|---:|---|---:|---|
| `etth1` | ETDataset ETT-small/ETTh1.csv | 7 | 1h | 17,420 | 마지막 365일 (8,760h) |
| `etth2` | ETDataset ETT-small/ETTh2.csv | 7 | 1h | 17,420 | 마지막 365일 (8,760h) |
| `weather` | darts weather.csv (Jena 2020, 21개 변수, 10분) | 21 | 10분 → **1h 평균 리샘플** | 8,783 | 마지막 180일 (4,320h) |
| `electricity20` | laiguokun electricity.txt.gz (321 고객, 1h) 중 **20개 채널** | 20 | 1h | 26,304 | 마지막 365일 (8,760h) |

- `electricity20` 채널 선택: `numpy.random.default_rng(2026).choice(321, 20, replace=False)` 를 정렬한 인덱스. 전체 321채널의 일 단위 재학습 캐시는 CPU 예산(4 vCPU)을 넘기 때문에 부분 집합을 씁니다. 이는 사전에 정한 제약이며 결과를 보고 고른 것이 아닙니다.
- 결측: ETT·electricity·weather 원본에는 결측이 없어야 하며, 파이프라인이 결측·중복 시각·비단조 시각을 검사해 하나라도 있으면 실패합니다(`metronome.data.schema`).
- 스트림 구간 이전의 모든 데이터가 **초기 학습 가능 구간**입니다.

## P3. 예측 과제

- 입력 길이 L = 336, 예측 길이 H = 96 (LTSF 표준).
- 다변량 입력 → 다변량 출력, 모든 채널을 평가.
- 스트림의 **매 시각 t**를 예측 기준(origin)으로 삼아 t+1..t+96 을 예측합니다. 따라서 스트림 길이 S 에 대해 S−96+1 개의 origin이 생깁니다(마지막 96개는 정답이 없어 제외).

## P4. 척도와 지표

- 각 채널은 **초기 학습 구간(스트림 이전 전체)의 평균·표준편차**로 표준화한 척도에서 평가합니다. 이 척도는 모든 정책과 모든 재학습에 대해 고정합니다. 재학습이 스케일러를 다시 맞추더라도 평가 척도는 바뀌지 않습니다.
- 주 지표: **MAE** (origin × horizon × channel 평균). 보조: MSE.
- 비용: 실제 수행한 재학습 횟수, 재학습에 쓴 학습 시간 합(초, 캐시 기록값).

## P5. 모델과 학습 레시피

재학습 정책 비교의 모델은 **DLinear** (Zeng et al. 2023) 한 가지로 고정합니다.

- 이동평균 커널 25, 채널 공유 선형층(`individual=False`), 입력 L=336 → 출력 H=96.
- 손실 MSE, Adam, 초기 lr 0.005, 매 epoch lr × 0.5 (공식 `lradj=type1`), 배치 32, 최대 10 epoch, 검증 MSE 기준 patience 3 조기 종료.
- 검증 구간: 해당 재학습에 쓸 수 있는 구간의 **마지막 14일** (윈도의 목표가 이 구간에 들어가는 윈도). 나머지가 학습.
- 스케일러: 해당 재학습의 학습 구간 통계로 다시 맞춤(전처리도 재학습의 일부).
- 시드: {0, 1, 2}. 시드는 가중치 초기화와 배치 순서를 결정합니다.
- 스레드: 재학습 1회당 `torch.set_num_threads(1)`, 4개 프로세스 병렬.

## P6. 재학습 캐시

정책을 공정하고 싸게 비교하기 위해, **콜드 스타트 재학습은 정책과 무관**하다는 사실을 이용합니다.
데이터셋 × 시드마다 스트림의 **매일 00:00** 에 그 시각까지의 데이터로 콜드 학습한 모델을 모두 만들어 둡니다(캐시).
어떤 정책이든 "d일에 재학습"은 캐시의 d일 모델을 꺼내 쓰는 것과 동일합니다.

- 기본 학습 창: **확장(expanding)** — 처음부터 d일 직전까지 전부.
- 변형(`etth1`, `etth2` 만): **슬라이딩** — 초기 학습 구간 길이와 같은 길이의 최근 창.
- 변형(`etth1`, `etth2` 만): **웜 스타트** — 전날 모델 가중치에서 시작해 최대 2 epoch, lr 0.001. 이것은 순차 의존이므로 캐시가 아니라 별도 순차 실행입니다.

캐시 항목마다 학습 시간(초), epoch 수, 검증 MSE, 가중치 SHA-256을 기록합니다.

## P7. 정책

모든 정책은 같은 캐시를 읽고, 스트림의 각 시각에 어느 날짜의 모델을 쓸지만 정합니다. 재학습된 모델은 **다음 날 00:00부터** 적용됩니다(재학습·배포에 하루 지연이 있다는 보수적 가정).

| 정책 | 규칙 | 격자 |
|---|---|---|
| `never` | 0일 모델 고정 | – |
| `periodic-k` | k일마다 재학습 | k ∈ {1, 3, 7, 14, 30, 60, 90} |
| `ratio-τ` | 최근 7일 MAE가 현재 모델의 **검증 MAE** × (1+τ) 를 넘으면 재학습. 재학습 후 7일 쿨다운 | τ ∈ {0.1, 0.2, 0.3, 0.5} |
| `ph-λ` | 일별 MAE 열에 Page–Hinkley (δ = 0.005, 최소 7일 워밍업) 적용, 누적 통계가 λ 를 넘으면 재학습 후 검정기 초기화 | λ ∈ {0.05, 0.1, 0.2, 0.4} |
| `adwin-δ` | 일별 MAE 열에 ADWIN(Bifet & Gavaldà 2007) 적용, 변화 검출 시 재학습 후 초기화 | δ ∈ {0.3, 0.1, 0.01, 0.001} |

- 감시 통계는 **스트림에서 실제로 관측 가능한 값**만 씁니다. t 시점의 일별 MAE는 t−96 이전 origin의 예측만 포함합니다(정답이 도착한 것만).
- 감시 통계의 척도는 P4와 같습니다.
- 격자의 모든 점을 보고하며 사후에 "최고 점"만 골라 비교하지 않습니다. 한 점을 대표로 언급할 때는 격자의 **중간값**(ratio-0.2, ph-0.1, adwin-0.01)을 먼저 보고합니다.

## P8. 통계

- 데이터셋 × 정책마다 시드 3개의 **평균**과 **최소–최대**를 보고합니다.
- `never` 대비, `periodic-1` 대비 MAE 차이의 95% 구간: 일 단위 블록(7일) 페어드 부트스트랩 1,000회, 시드별로 계산한 뒤 시드 평균.
- 개선율 = (MAE_never − MAE_policy) / MAE_never.

## P9. 사전 가설과 판정 기준

| 가설 | 판정 기준 |
|---|---|
| H1 재학습은 도움이 된다 | 4개 데이터셋 모두에서 `periodic-1` 이 `never` 보다 MAE 낮고, 95% 구간 하한 > 0 |
| H2 감시 기반 정책은 적은 재학습으로 대부분의 이득을 얻는다 | 어떤 데이터셋에서든 격자의 대표점(ratio-0.2 / ph-0.1 / adwin-0.01) 중 하나가 `never→periodic-1` 이득의 80% 이상을 재학습 횟수 ≤ 91회(periodic-4 상당, 1년의 1/4)로 달성 |
| H3 웜 스타트는 콜드와 같은 정확도를 1/3 비용으로 낸다 | `etth1`, `etth2` 에서 웜 스타트 일 재학습 MAE 가 콜드 일 재학습 MAE 의 +1% 이내이고 학습 시간 합이 1/3 이하 |
| H4 확장 창이 슬라이딩 창보다 낫다 | `etth1`, `etth2` `periodic-7` 에서 확장 창 MAE ≤ 슬라이딩 창 MAE |

가설이 기각되어도 결과는 그대로 보고합니다.

## P10. 논문 재현 (별도 실험)

DLinear(Zeng et al. 2023)와 PatchTST(Nie et al. 2023)를 **표준 LTSF 프로토콜**로 학습해 논문 보고값과 대조합니다.

- 분할: ETTh — 학습 12개월, 검증 4개월, 시험 4개월 (공식 코드 `border` 와 동일: 12·30·24 / 16·30·24 / 20·30·24 시간, 검증·시험 구간 앞에 L 만큼 겹침).
- 표준화: 학습 구간 통계. 지표: 표준화 척도의 MSE·MAE (논문과 동일).
- DLinear: L=336, H ∈ {96, 192, 336, 720}, 레시피는 P5와 같음(공식 스크립트 lr 0.005). 시드 2021.
- PatchTST/42: L=336, H=96, patch 16, stride 8, d_model 16, heads 4, layers 3, d_ff 128, dropout 0.3, fc_dropout 0.3, head_dropout 0, RevIN, lr 1e-4 OneCycle(pct_start 0.3), 배치 128, 최대 100 epoch, patience 20, 시드 2021. CPU 예산 때문에 H=96 만 실행합니다.
- 판정: 논문 보고값 대비 **MSE 상대 오차 ±3% 이내**면 재현으로 봅니다. 벗어나면 원인을 적고 수치는 그대로 남깁니다.
- 논문 보고값은 `artifacts/paper_reference.json` 에 표 번호와 함께 옮겨 적었습니다. 이 사본은 사람이 옮긴 값이므로 원문과 대조해 확인해야 합니다.

## P11. 추론 최적화 (별도 실험)

- 대상: `etth1` 캐시의 0일 DLinear 모델과 P10 의 PatchTST 모델.
- 경로: PyTorch eager(`inference_mode`, 1 thread) · ONNX Runtime FP32 (1 intra-op thread, sequential) · ONNX Runtime 동적 INT8.
- 동일 float32 NumPy 입력, 배치 {1, 16, 64}, 워밍업 50회, 측정 300회, 엔진 순서는 라운드마다 교대.
- 보고: p50·p95 지연(ms), 처리량, 모델 파일 크기, PyTorch 대비 최대 절대 출력 편차. **편차가 1e-4 (FP32) 를 넘으면 실패**로 기록하고 INT8 은 편차를 그대로 보고합니다.
- 이 수치는 모델 호출 지연이며 HTTP 응답시간이 아닙니다. HTTP 는 별도로 측정합니다.

## P12. 대규모 데이터 처리 (별도 실험)

- 대상: M4 전체(100,000 시계열, 6개 주기, 와이드 CSV ≈ 250MB), Electricity 321채널, Traffic 862채널.
- 작업: 와이드 → 롱 변환, 결측 제거, 시계열별 길이·평균·표준편차 집계, Parquet 분할 저장, 재읽기 후 셀 수 대조.
- 엔진: Polars(스트리밍) · pandas · PySpark `local[4]`. 각 3회 실행, 중앙값 보고. 셀 수가 세 엔진에서 같아야 통과.

## P13. 서비스 검증
